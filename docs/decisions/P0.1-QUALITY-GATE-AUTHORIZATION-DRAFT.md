## 1. Mục tiêu

Trước khi có code sản phẩm, repo có một **quality gate** chạy được bằng một lệnh, chạy cả local lẫn CI trên mọi PR. Gate cho ra kết quả đúng: checker không còn FAIL giả.

## 2. Trong boundary

1. **Sửa `scripts/product-check.mjs`** (bản của project): bỏ escape thừa `\\` trong regex literal để kiểm đúng filename, frontmatter và status.
   - Ghi entry vào `docs/ai/framework-history.md` dưới `## v4.4`. Đây là thay đổi checker, không phải Core.
   - Soạn sẵn mô tả lỗi và bản vá để HUMAN LEAD gửi lên repo kit `ai-dev-framework`. Không push sang repo kit.
2. **Test cho checker** bằng `node --test` (stdlib, không dependency):
   - REQ hợp lệ PASS;
   - thiếu frontmatter FAIL;
   - READY còn open question FAIL;
   - tên file sai FAIL.
3. **Quality gate một lệnh:** `scripts/quality-gate.mjs` (Node stdlib), chạy:
   - `framework-check.mjs`;
   - `product-check.mjs` cho mọi `docs/product/requirements/REQ-*.md`;
   - `node --test`;
   - kiểm repo không chứa file cấm: media `*.mp4`, `*.mov`, `*.wav`, `*.mp3` > 1 MB trong git; file `.env` / `config.toml`; file > 5 MB.
   - Từ P1a gate tự chạy thêm `python -m pytest -q` khi có `pyproject.toml`. P0.1 chỉ để chỗ móc, không thêm Python.
4. **CI GitHub Actions** `.github/workflows/quality.yml`:
   - chạy quality gate trên `pull_request` và `push` vào `main`;
   - Ubuntu runner, Node 24;
   - action pin theo major version đã phổ biến (`actions/checkout`, `actions/setup-node`).
5. Cài file còn treo `.github/workflows/requirement-to-task.yml` của adapter Claude Code (bản gốc: `adapters/claude-code/workflows/`).
6. Cập nhật `FRAMEWORK_ADOPTION.md` (Verification status), `docs/ai/project-profile.md` §9 (lệnh quality gate), `docs/workflow/current-state.md`.
